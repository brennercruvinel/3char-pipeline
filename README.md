# 3char-pipeline

build pipeline for the [3char](https://huggingface.co/datasets/brennercruvinel/3char) dataset: 64 parsers that read code lists published by their assigning authorities and emit one parquet per system in a common schema, plus the checks that gate the upload. this repository holds code and provenance records only. it holds no raw sources and no parquet.

## requirements

python 3.11 or later, [uv](https://docs.astral.sh/uv/), network access to the urls in `systems.tsv`. about 2 gb of disk for the raw sources.

```bash
uv venv .venv && uv pip install --python .venv/bin/python -r pipeline/requirements.txt
```

## build

```bash
.venv/bin/python pipeline/download.py     # fetch every raw source; verify sha256 against CHECKSUMS.tsv
.venv/bin/python pipeline/build.py        # run the 64 parsers; one parquet per system under data/<domain>/<id>/
.venv/bin/python pipeline/validate.py     # every code against its system's code_pattern; non-zero exit on any mismatch
.venv/bin/python pipeline/build_hub.py    # select the publishable systems, write hub/ (parquet, systems.parquet, CHANGELOG.md)
.venv/bin/python pipeline/build_card.py   # write hub/README.md: yaml and systems tables from systems.parquet, prose from pipeline/card_body.md
```

`download.py` exits non-zero when a file's sha256 differs from `CHECKSUMS.tsv`. an upstream change is adopted with `--accept-new`, which rewrites the manifest entry; the change is then recorded in `CHANGELOG.md`. `validate.py` treats `pipeline/known_exceptions.py` as the only allowed mismatches; each entry carries the reason.

## data architecture

```
data/<domain>/<id>/raw/<file>      raw source as fetched, never rewritten, never committed
data/<domain>/<id>/<id>.parquet    parser output, schema in SCHEMA.md
hub/                                the upload: data/<domain>/<id>.parquet for publishable systems, systems.parquet, README.md, CHANGELOG.md
```

`systems.tsv` is generated by `build_systems.py` from `pipeline/systems_meta.py` plus what is on disk: 64 rows, 15 columns, documented in `SCHEMA.md`. `systems.parquet` in `hub/` is the same table restricted to published systems.

## provenance

for each system `systems.tsv` records the assigning authority and, separately, the url the file was fetched from, because the two often differ and the difference is the provenance. `CHECKSUMS.tsv` records sha256 and size of every raw file; `versions.py` reads the version string each source publishes out of the file itself, so it cannot go stale. `retrieved_at` is the fetch date.

`LICENSES.md` is the triage of all 64 sources against the authority's own terms, with verbatim quotes. systems whose authority forbids redistribution are parsed and never written to `hub/`. `history/SOURCES.tsv` is the table the project started from and is kept only as a record.

## validation

two layers, both reproducible from this repository:

- `validate.py`: every emitted code matches its system's anchored regex. `pattern_status` in `systems.tsv` says whether the regex was written against the real file (`derived`) or is still loose (`provisional`). all 58 published systems are `derived`.
- `crosscheck_wikidata.py`: every published code, full match, against the Wikidata format constraint (P1793) of the matching property, for the 13 systems that have one. the regex table is in `external/` with its retrieval date; the comparison forms (dotted ICD-10-CM, full UN/LOCODE, BCP 47 language subtags only) are documented in the script.

`census.py`, `keys.py` and `manifest.py` produce the statistics, the identification keys and the deposit manifest that the dataset card cites. `card_check.py` compares every number in `hub/README.md` with their output and exits non-zero on a difference.

## writing a parser

```python
from core import parser, row, read_csv

@parser("cmp/sts")
def http_status(path, sysrow):
    for r in read_csv(path):
        yield row("cmp/sts", r["Value"], r["Description"], extra={"reference": r.get("Reference")})
```

register one function per system id, yield canonical rows, add the system to `systems_meta.py` with its authority, url, license and a regex written against the file. run `validate.py`. a code that fails the regex is a parser bug or a pattern bug until proven to be a malformed source row, in which case it goes in `known_exceptions.py` with the reason.

## contributing

issues and pull requests are welcome. a pull request that adds or changes a system includes: the `systems_meta.py` entry, the parser, the `CHECKSUMS.tsv` line, the `LICENSES.md` row with the quoted terms, and a `CHANGELOG.md` entry. the build must pass `validate.py`.
