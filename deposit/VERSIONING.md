# Versioning, releases and citation

This document sets out how releases of the 3char dataset and its related repositories are numbered, what a dataset release contains, and how each artifact should be cited. Release tags and a Zenodo deposit have not been created yet; the sections below describe the policy they will follow.

## Data and software

| Artifact | Kind | Location | Identifier |
| --- | --- | --- | --- |
| The 58 Parquet files, `systems.parquet`, the dataset card and the changelog | Data | Hugging Face Hub; Zenodo once deposited | Hub commit; once deposited, a Zenodo DOI per version and a concept DOI |
| 3char-pipeline | Software | GitHub | Git tag and `CITATION.cff`; optionally a Zenodo DOI through GitHub release archiving |
| 3char-bench | Software and its measured output (`rig/out/*.json`) | GitHub | Git tag and `CITATION.cff` |
| poc-nsi | Software, raw model outputs and study documents | GitHub | Git tag and `CITATION.cff` |

## Version numbers

The dataset uses `MAJOR.MINOR.PATCH`. A change to the schema increments MAJOR. A release that changes any Parquet file, including adding or removing a system, increments MINOR. A release that changes only the card or the changelog increments PATCH.

The pipeline's version equals the version of the dataset it builds. 3char-bench and poc-nsi are versioned independently.

Each dataset version will become a Zenodo version under one concept DOI, and the Hub will keep the same files at the tagged revision. `CHANGELOG.md` is the only changelog: it is maintained in the pipeline and copied to the Hub by `build_hub.py`.

## Contents of a dataset release

1. The publishable Parquet files and `systems.parquet`, identical to the files on the Hub at the tagged revision.
2. `MANIFEST.tsv`, with the SHA-256, size in bytes and row count of each file, regenerated by `manifest.py`.
3. `README.md` (the dataset card), `CHANGELOG.md`, `SCHEMA.md` and `LICENSES.md`.
4. `census.json`, `keys.json`, `equivalences.json` and `crosscheck_wikidata.json`, with the scripts that produce them and the external constraint table with its retrieval date.
5. `zenodo_metadata.json`, as deposited.

## Update cadence

There is no fixed cadence. Sources with yearly editions, such as ICD-10-CM and tzdb, are refreshed when a new edition appears. `download.py` detects any upstream change by SHA-256, and no change is adopted silently.

## Citation

Once the deposit exists, cite the dataset by its version DOI; until then, cite it with the BibTeX entry in the dataset card, which gives the version and the Hub URL. Cite the pipeline, 3char-bench or poc-nsi with their `CITATION.cff` files.
